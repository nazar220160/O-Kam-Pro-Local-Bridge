# O-Kam Pro Local Bridge

**Ваши камеры. Ваша сеть. Ваш API.**

[![Версия 0.6.0](https://img.shields.io/badge/version-0.6.0-95d75d)](CHANGELOG.md)
[![Лицензия MIT](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

Локальная веб-панель и HTTP API для совместимых камер O-Kam Pro с протоколом CS2/PPPP: видео, несколько объективов, PTZ, метаданные и проверяемые команды управления.

[English](README.md) · [Развёртывание](docs/deployment.md) · [API](docs/api.md) · [Безопасность](SECURITY.md)

## Возможности и ограничения

Поддерживаются снимки, MJPEG, исходный H.264, переключение качества high/medium/low, несколько объективов (в том числе три при поддержке камерой), PTZ, предустановки и зависящие от прошивки настройки.

Совместимы не все камеры с названием O-Kam: требуется транспорт CS2/PPPP и доступ к камере по локальной или маршрутизируемой частной сети. Вход в аккаунт и начальная настройка транспорта используют сервисы производителя. Передачи видео через облачный ретранслятор или WAN здесь нет.

Не реализованы звук, двусторонняя связь, воспроизведение записей с SD, транспорт VP и собственный RTSP-сервер моста. Флаг поддержки ONVIF/RTSP не подтверждает работу соответствующего сервиса. Отдельные переключатели этих сервисов не проверены и отключены в интерфейсе.

## Быстрый запуск

Рекомендуемая среда — Docker Engine на Linux и Docker Compose с сетью хоста.

```sh
git clone https://github.com/nazar220160/O-Kam-Pro-Local-Bridge.git
cd O-Kam-Pro-Local-Bridge
```

Если аккаунт выдаёт **зашифрованные пароли камер**, сначала поместите собственный совместимый устаревший официальный `SuperIPCam.exe` в `secrets/SuperIPCam.exe`. Проект не распространяет и не скачивает этот файл. Он читается только как данные для расшифровки паролей и никогда не запускается. Подходят не все версии клиента.

```sh
docker compose up -d
```

Откройте [localhost:8080](http://localhost:8080), войдите в аккаунт O-Kam и подключите выбранную камеру. Compose собирает API и веб-панель, автоматически создавая приватный токен шлюза.

По умолчанию веб-панель доступна на `127.0.0.1:8080`, API — на `127.0.0.1:8098`. Документация: [API](http://localhost:8080/docs/) и [OpenAPI JSON](http://localhost:8080/openapi.json).

Для доступа из доверенной локальной сети создайте `.env`:

```dotenv
WEB_LISTEN=0.0.0.0
WEB_PORT=8080
BRIDGE_PORT=8098
```

Повторите `docker compose up -d`. Для удалённого доступа используйте защищённую сеть или HTTPS-шлюз; см. [руководство](docs/deployment.md). В Docker Desktop может потребоваться включить сеть хоста; UDP-поиск не гарантирован.

## API без Docker

Нужны Python 3.12+, FFmpeg в `PATH` и зависимости:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m okam_bridge api --port 8098
```

Для зашифрованных паролей добавьте `--credential-client /path/to/SuperIPCam.exe`. Веб-панель запускается отдельно из `web/`. Примеры авторизации, видео и управления — в [docs/api.md](docs/api.md).

Независимый общественный проект, не связанный с O-Kam или VStarcam. Лицензия [MIT](LICENSE); происхождение стороннего кода — [THIRD_PARTY.md](THIRD_PARTY.md).

### Docker Desktop (macOS / Windows)

```sh
docker compose -f compose.yaml -f compose.desktop.yaml up -d
```

В этом варианте web-порт публикуется обычным способом, API остаётся внутри Docker. Укажите IP камеры вручную: LAN broadcast может не проходить через NAT виртуальной машины. Для Compose требуется поддержка тега `!reset` (версия 2.24.4+).
