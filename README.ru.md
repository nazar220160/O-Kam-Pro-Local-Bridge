# O-Kam Pro Local Bridge

**Ваши камеры. Ваша сеть. Ваш API.**

Локальная веб-панель и HTTP API для совместимых камер O-Kam Pro с протоколом CS2/PPPP: видео, несколько объективов, PTZ, метаданные и проверяемые команды управления.

## Возможности и ограничения

Поддерживаются снимки, MJPEG, исходный H.264, переключение качества high/medium/low, несколько объективов (в том числе три при поддержке камерой), PTZ, предустановки и зависящие от прошивки настройки.

Совместимы не все камеры с названием O-Kam: требуется транспорт CS2/PPPP и доступ к камере по локальной или маршрутизируемой частной сети. Вход в аккаунт и начальная настройка транспорта используют сервисы производителя. Передачи видео через облачный ретранслятор или WAN здесь нет.

Дополнительно можно включить публикацию RTSP/TCP через отдельный MediaMTX (порт 8554): H.264 копируется без перекодирования. Фасад ONVIF Device/Media (порт 8899) предоставляет профиль для каждого обнаруженного объектива и снимки с авторизацией. WS-Discovery зависит от доступности multicast. Через ONVIF доступны непрерывный поворот/наклон с ограничением времени, нативные предустановки, PullPoint-события из состояния камеры, поиск записей и прямое воспроизведение клипов. Есть запись на сервер с квотой/сроком хранения и импорт клипов с SD-карты. Абсолютные координаты PTZ, обратное воспроизведение и RTSP-поиск по времени не поддерживаются; сертификация ONVIF не заявляется. [Настройка VLC и NVR](docs/bridge-exports.md).

Для совместимых камер звук G.711 A-law передаётся в RTSP как AAC. Двусторонняя связь и транспорт VP не реализованы. Флаг поддержки ONVIF/RTSP самой камерой не подтверждает работу её сервисов. Их отдельные переключатели остаются непроверенными и отключёнными; экспорт моста не меняет нативные настройки ONVIF/RTSP камеры.

У публикации отдельные временные данные входа, которые автоматически отображаются открытым текстом при включённом экспорте. Сессия, подключения камер, качество, настройки записи и данные ONVIF/RTSP сохраняются в зашифрованном хранилище. После перезапуска они восстанавливаются автоматически; адреса потоков и пароли остаются прежними. Повторно настраивать Frigate не нужно. Явный выход из аккаунта удаляет сохранённую сессию; выключенный экспорт и отключённые камеры остаются выключенными.

## Быстрый запуск

Рекомендуемая среда — Docker Engine на Linux и Docker Compose с сетью хоста.

```sh
git clone https://github.com/nazar220160/O-Kam-Pro-Local-Bridge.git
cd O-Kam-Pro-Local-Bridge
```

Расшифровка паролей камер встроена в мост. Официальный PC-клиент, `SuperIPCam.exe` и дополнительные файлы не нужны.

```sh
docker compose up -d
```

Откройте [localhost:8080](http://localhost:8080), войдите в аккаунт O-Kam и подключите выбранную камеру. Compose собирает API и веб-панель, автоматически создавая приватный токен шлюза.

По умолчанию веб-панель доступна на `http://IP_СЕРВЕРА:8080`, API — на `127.0.0.1:8098`. Документация: [API](http://localhost:8080/docs/) и [OpenAPI JSON](http://localhost:8080/openapi.json).

Параметры можно переопределить в `.env`:

```dotenv
WEB_LISTEN=0.0.0.0
WEB_PORT=8080
BRIDGE_PORT=8098
```

Повторите `docker compose up -d`. Для удалённого доступа используйте защищённую сеть или HTTPS-шлюз; см. [руководство](docs/deployment.md). На macOS используйте `./start-macos.sh`: UDP камеры обрабатывается нативно, веб-панель и MediaMTX запускаются в Docker.

## API без Docker

Нужны Python 3.12+, FFmpeg в `PATH` и зависимости:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m okam_bridge api --port 8098
```

Пароли камер расшифровываются автоматически, без дополнительных файлов. Веб-панель запускается отдельно из `web/`. Примеры авторизации, видео и управления — в [docs/api.md](docs/api.md).

Независимый общественный проект, не связанный с O-Kam или VStarcam. Лицензия [MIT](LICENSE); происхождение стороннего кода — [THIRD_PARTY.md](THIRD_PARTY.md).

### macOS

```sh
./start-macos.sh
```

Нужны Python 3.11+, FFmpeg и Docker Desktop. Мост запускается непосредственно в macOS, web-панель и MediaMTX запускаются в отдельных контейнерах. Это обходит блокировку ответов камеры с динамических UDP-портов в Docker Desktop. Настройки портов берутся из `.env`. Логи и PID моста находятся в `.runtime/`; этот каталог исключён из Git.

All-container вариант `compose.desktop.yaml` остаётся экспериментальным: указание IP камеры не гарантирует доступность UDP через виртуальную сеть.
